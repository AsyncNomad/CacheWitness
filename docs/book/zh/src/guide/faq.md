# 常见问题

### 它和 failpoint（RocksDB SyncPoint、fail-rs、Go failpoint）有什么不同？

那些工具在单个进程内、编译进该进程测试的具名位置暂停代码或让它失败。CacheWitness 采用相同的思路，但**通过 Redis 跨进程、跨服务器协调**，用**针对运行中应用的 HTTP 请求**来驱动交错，并提供**缓存专用的模式和判定**（陈旧值、回填、严格或有上限的陈旧）。

### 它和 Lincheck、Fray、Coyote 有什么不同？

那些工具在单个 JVM 或 .NET 运行时内探索线程交错。CacheWitness 在连接真实数据库与 Redis 的请求层面工作，每个模式强制一种交错，而不是搜索所有交错。

### 它能发现我不知道的竞态吗？

不能。模式和钩子位置由你决定。它给你的是针对你所怀疑的竞态的确定性测试，以及区分真修复与看似合理的修复的方法。在多个钩子点之间自动探索顺序的功能在[路线图](../project/roadmap.md)上。

### 它能告诉我竞态在生产环境中多常发生吗？

不能。在合成负载下测得的比率，即使在条件相同的运行之间也差异很大（我们的测量中从 2.5 倍到约 38 倍），对生产环境几乎说明不了什么。案例研究只在判断一个缺陷是否值得修复时才引用这些数字。

### 把钩子留在生产代码里安全吗？

设计上是安全的：没有 `CAWIT_SYNC_URL` 时它在做任何工作之前就返回，在 `NODE_ENV=production` 下除非 `CAWIT_ALLOW_PRODUCTION=1` 否则保持关闭。不过它终究是测试用的埋点；有些团队更愿意把它放在自己的特性开关或仅测试使用的包装后面。

### 一定需要两个应用实例吗？

不需要。被暂停的调用在自己的 Redis 连接上等待，所以竞争请求可以经过同一个实例。两个实例更接近生产环境。

### 我的应用不是用 Node 写的。

执行器不关心应用用什么语言编写。你需要一个对应语言的钩子；[协议](../reference/hook-protocol.md)只是几个 Redis 命令。Python 钩子已在计划中。

### 它支持 MySQL、Redis Cluster、Memcached 或 Valkey 吗？

- **Valkey**：支持，它使用 Redis 协议。
- **MySQL**：暂不支持；检查从 PostgreSQL 读取已提交的值。MySQL 支持已在计划中。
- **Redis Cluster**：暂不支持；执行器和钩子在协议中使用一个 Redis 连接和单节点的键空间。只要你的 `cache_key` 检查不需要集群（改用 `app_view`），即使缓存是集群，协议用的 Redis 也可以是单独的单节点。
- **Memcached**：协议需要 Redis，但通过 `app_view` 判定时，你的缓存可以是任何东西。

### 为什么不用一个延迟缓存命令的代理来代替钩子？

我们测量过：在连接级代理中延迟命令会产生队头阻塞，与真实的慢回填相比会把竞态比率放大 10 到 40 倍，而且无法在应用中的精确位置暂停。见[项目的实验记录](https://github.com/AsyncNomad/CacheWitness/blob/main/docs/design/experiments-summary.md)（韩文）。

### 没有失败时，为什么结果是 `2` 而不是 `0`？

因为有些轮次什么也没测到。一个在重构、更换打包工具或修改配置之后悄悄不再到达同步点的测试套件，绝不能显示为绿色。
