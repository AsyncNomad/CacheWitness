# 로드맵

CacheWitness는 관문 방식으로 개발합니다. 각 단계는 측정 가능한 관문으로 끝나고, 관문마다 계획을 다시 판단합니다.

| 버전 | 초점 | 상태 |
|---|---|---|
| **0.1** | verify 모드: 시나리오, 패턴 세 개, Node 훅, CI 리포트 | 완료, 배포 대기 |
| 0.2 | 수정 레시피: 패턴마다 문서화·검증된 수정(다시 읽기 있는 리스, 버전 표식 무효화, 세대 번호 확인), 캐시 라이브러리·ORM 메인테이너에게 제안 | 다음 |
| 0.3 | check 모드(보조): Redis와 PostgreSQL WAL을 관찰해 코드 변경 없이 낡은 캐시 상태 확인, 실패 회차를 관측된 사건 순서로 설명, 압축된 값의 디코더 | 계획 |
| 1.0 | Python 훅, GitHub Action, 프레임워크별 시나리오 가이드, 호환성 매트릭스 | 계획 |

반응에 따라 검토 중인 것:

- **끼어들기 탐색**: 여러 동기화 지점 사이의 모든 순서를 자동으로 돌려, 사용자는 패턴만 고르고 순서는 도구가 찾음
- 캐시 라이브러리(keyv, cache-manager)용 **자동 훅**: `set`을 감싸 흔한 경우엔 앱 코드 변경이 필요 없게
- **훅 버전 진단**: 훅이 프로토콜 버전을 남기고, 실행기가 옛 훅 때문에 생긴 `NOT_REACHED`를 설명
- 판정하지 않는 **준비 회차**: 콜드 스타트를 결과에서 제외
- 미리 빌드한 바이너리, MySQL, 레플리카 지연 재충전·목록/집계 캐시 패턴

관문과 기각한 대안이 담긴 자세한 계획은 [`docs/PLAN.md`](https://github.com/AsyncNomad/CacheWitness/blob/main/docs/PLAN.md)에 있습니다.
